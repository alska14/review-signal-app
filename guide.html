연결 안내서

다른 AI에게 일을 시키고 결과를 이 앱에 복사해 붙여 넣는 것이 번거롭다면, AI 도구가 이 앱의 점검 기능을 직접 부르게 연결할 수 있습니다. 코딩을 몰라도 아래 순서대로 따라 하면 됩니다.

먼저 알아둘 것

  • 이 안내서의 연결은 모두 내 컴퓨터 안에서만 동작합니다. 점검할 글을 인터넷 서버로 보내지 않고, 로그인·API 키·이메일이 필요 없습니다.
  • 자동 점검이 하는 일: 원문과 AI 결과의 숫자·소수 자릿수·기호·ID·항목 수를 기계적으로 맞춰 봅니다. 뜻이 맞는지, 계산이 옳은지는 모릅니다. '문제를 못 찾음'은 '문제없음'이 아닙니다.
  • 더 깊은 확인(재검토 AI의 확신도와 검토 필요 판단, 균형정확도 점수)은 앞 화면의 방법이나 아래 MCP 연결로 이어서 할 수 있습니다.

어떤 방법을 고를까요?

방법이럴 때준비물난이도
화면에서 바로가끔 한 번씩, 붙여넣기로 충분할 때브라우저뿐가장 쉬움
주소로 열기다른 도구가 주소만 열어도 결과를 읽게 하고 싶을 때브라우저뿐쉬움
MCP 연결Claude Code·Claude Desktop·Codex 안에서 "이 결과 점검해 줘"라고 말만 하고 싶을 때Node.js, 이 앱의 ZIP보통(10분)
내 컴퓨터 API직접 만든 프로그램이나 자동화에서 호출하고 싶을 때Node.js, 이 앱의 ZIP보통

1단계 공통 준비: Node.js와 폴더

  1. Node.js 설치 확인: 터미널(Windows는 PowerShell)을 열고 node -v 를 입력합니다. v18 이상 숫자가 나오면 됩니다. 안 나오면 nodejs.org 에서 LTS 버전을 설치하세요.
  2. 폴더 준비: 앱 ZIP(review_signal_app.zip)을 새 폴더에 풉니다. 안에 mcp 폴더와 logic.js 가 보여야 합니다.
  3. 폴더 경로 확인: 풀어 둔 폴더의 전체 경로를 복사해 두세요. 예: C:\tools\review-signal. 아래에서 폴더경로 자리에 넣습니다.
  4. 시험: 그 폴더에서 node --test tests/logic.test.js tests/check.test.js tests/mcp.test.js 를 실행해 모두 통과(pass)하는지 봅니다.

2단계 A: MCP로 AI 도구에 연결하기

MCP는 AI 도구가 외부 기능(여기서는 점검 기능)을 부르는 공통 방식입니다. 한 번 등록해 두면 AI에게 말로 시킬 수 있습니다.

Claude Code (터미널용)

claude mcp add --transport stdio review-signal -- node 폴더경로/mcp/server.mjs

Claude Desktop

설정 파일 claude_desktop_config.json 의 mcpServers 에 아래를 넣고 앱을 다시 켭니다. (Windows에서는 경로의 역슬래시를 \\ 두 개로 씁니다.)

{
  "mcpServers": {
    "review-signal": {
      "command": "node",
      "args": ["폴더경로/mcp/server.mjs"]
    }
  }
}

Codex

~/.codex/config.toml 에 아래를 추가합니다.

[mcp_servers.review-signal]
command = "node"
args = ["폴더경로/mcp/server.mjs"]

잘 연결됐는지 확인

AI 도구에서 이렇게 말해 보세요.

review-signal 도구의 verify_completion 으로 아래 두 글을 점검해 줘.
[원문] B#2 값 0.9685245400, 허용 오차 ±0.5
[결과] B#2 0.96852454, 허용 오차 0.5 — 모두 완료

"소수 자릿수 손실", "기호 누락", "완료 주장과 불일치"가 나오면 성공입니다.

쓸 수 있는 도구

  • verify_completion: 원문 대조 + 재검토 프롬프트 + 다음 단계 안내를 한 번에
  • check_against_source: 원문 대조만
  • build_review_prompt, parse_review_json, score_review_signal: 재검토 프롬프트 만들기, 돌려받은 JSON 읽기, 점수 계산
  • paper_models: 논문 모델 11종 결과
  • 프롬프트 verify-completion: 지원하는 앱에서는 슬래시 메뉴로도 고를 수 있습니다.

시험 상태: 직접 만든 요청으로 연결 과정과 도구 호출이 맞게 응답하는 것은 확인했습니다. 위 세 앱에 실제로 등록해 본 시험은 하지 못했으므로, 안 되면 앱의 MCP 로그와 경로(공백이 있으면 따옴표)를 먼저 확인하세요.

2단계 B: 내 컴퓨터 API로 부르기

같은 기능을 주소로 부릅니다. 이 컴퓨터(127.0.0.1)에서만 열리고 밖에서는 접근할 수 없습니다.

  1. 폴더에서 서버를 켭니다: 
    node mcp/server.mjs --http 8787
    창은 닫지 마세요. (끄려면 Ctrl+C)
  2. 다른 터미널에서 확인: 
    curl http://127.0.0.1:8787/health
  3. Windows PowerShell에서 점검 요청 보내기: 
    $body = @{ requirement = "B#2 값 0.9685245400"; result = "B#2 0.96852454 — 모두 완료" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/api/verify `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
  4. macOS·Linux: 
    curl -s -X POST http://127.0.0.1:8787/api/verify -H "Content-Type: application/json" \
  -d '{"requirement":"B#2 값 0.9685245400","result":"B#2 0.96852454 — 모두 완료"}'

주소 목록

  • POST /api/verify: requirement, result → 원문 대조 + 재검토 프롬프트 + 다음 단계
  • POST /api/check: source, output → 원문 대조만
  • POST /api/prompt, POST /api/parse, POST /api/score, GET /api/models, GET /health

주소로 열어서 읽게 하기(설치 없음)

브라우저를 다루는 AI 에이전트에게는 아래 주소를 열게 하고, 화면의 "기계가 읽는 결과(JSON)" 칸을 읽게 하면 됩니다. 줄은 ; 로 구분합니다.

https://alska14.github.io/review-signal-app/?lines=예,구체적 오류 지적,오답;아니오,정답

막혔을 때

  • node 를 찾을 수 없다고 나옴: Node.js를 설치한 뒤 터미널을 새로 여세요.
  • MCP에 도구가 안 보임: 경로가 틀렸거나 공백이 있는 경우가 많습니다. 경로를 따옴표로 감싸고 앱을 다시 켜세요. 터미널에서 node 폴더경로/mcp/server.mjs 를 직접 실행해 오류가 나는지 보세요(아무 출력 없이 대기하면 정상).
  • 포트가 이미 사용 중: --http 8788 처럼 다른 번호를 쓰세요.
  • 한글이 깨짐(PowerShell): 위 예시처럼 UTF-8로 바꿔 보내세요.

호스팅 API 키(온라인에서 부르는 방식)는 아직 없습니다

위 방법은 모두 내 컴퓨터에서 도는 방식이라 키가 필요 없습니다. 인터넷 주소로 어디서나 부르는 API와, 이메일 확인 뒤 키를 발급하는 방식은 아직 만들지 않았습니다. 이메일을 모으려면 별도 서버, 개인정보 안내, 인증 메일 발송이 필요해서 준비 중이며, 만들어지기 전에는 이 페이지에 이메일을 받는 칸이 없습니다.

이 앱은 논문 「언어모델의 정답률과 추가 검토 요청의 일치와 불일치」의 재검토 방식을 쓰며, 자동 원문 대조와 연결 기능은 앱이 추가한 확장입니다. AI와 함께 만들었습니다.
