# 검토 신호 점검기

논문 「언어모델의 정답률과 추가 검토 요청의 일치와 불일치」(10번 과제)의 결과를 쓰는 앱입니다.

**이 앱은 AI 답변을 업무에 쓰는 사람이, AI가 붙인 '다시 검토 필요' 표시가 실제 오답을 얼마나 가려냈는지 내 기록 몇 줄로 계산해 보도록 돕습니다.**

## 열어 보는 법 (둘 중 하나)
- 공개 주소: https://alska14.github.io/review-signal-app/ (로그인 없음)
- 내려받은 묶음: 새 폴더에 ZIP을 풀고 `index.html` 을 더블클릭하면 브라우저에서 열립니다. 설치·서버·인터넷·API 키가 필요 없습니다.

## 사용자가 앱에서 하는 일 세 가지
1. **내 기록 입력** — AI 답변마다 ① AI가 '검토 필요'라고 했는지 ② 그 근거 ③ 내가 확인한 실제 결과(정답/오답)를 고릅니다. `예시로 채우기` 버튼이 가상의 예시 14줄을 넣어 줍니다.
2. **점수와 논문 모델 비교** — 오답 검토율, 정답 검토율, 균형정확도를 계산하고, 논문의 OpenAI 7종·Claude 4종 결과 사이에 내 점수를 놓아 보여 줍니다.
3. **논문 사례로 연습** — 논문에 나온 실제 사례 4개에서 AI의 수정안을 따를지 고르고, 논문이 확인한 정답과 비교합니다.

## 논문의 어느 결과를 쓰나요
- 계산식(논문 3.4절): 균형정확도 = (오답 검토율 + 1 − 정답 검토율) / 2. 오답 또는 정답이 0건이면 0%가 아니라 '계산 불가'로 표시합니다.
- 모델별 TP·FN·FP·TN 숫자: 논문 표 1·2, `data_models.js` (논문의 분석 파일 analysis_sensitivity.json·analysis_content.json 에서 모델별 TP·FN·FP·TN·Brier 만 옮김).
- 연습 사례 4개: 논문 4.2·4.3절과 부록 A1, `data_cases.js`.
- 해석 문구: 논문의 주의를 옮겼습니다(검토 요청은 오류 확정이 아님, 오답이 적으면 일반화하지 않음, '검산 부족'과 '구체적 오류 지적'을 구분).

## 검사
Node.js 18 이상이 있으면(없어도 앱은 열립니다):
```
node --test tests/logic.test.js
```
논문의 균형정확도 숫자, 계산 불가 처리, 잘못된 입력에서 멈추지 않는지를 확인하는 9개 시험입니다.

## 데이터와 비밀값
- 앱에 들어 있는 데이터는 논문의 공개 가능한 집계 숫자와 가상 예시뿐입니다. 실제 개인정보나 고객 자료는 없습니다.
- AI 서비스 키가 필요 없고 소스·화면에 비밀값이 없습니다. 입력한 기록은 브라우저 안에서만 계산되고 서버로 보내거나 저장하지 않습니다.

## 한계
논문은 합성 문제 12개로 한 탐색 연구이고, 정답률과 검토 요청의 일반적 관계는 확정하지 못했습니다. 이 앱의 해석은 참고용입니다. 논문과 이 앱은 AI의 도움을 받아 썼습니다.
